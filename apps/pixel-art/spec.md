## 1. 한 줄 소개와 완성 화면

**한 줄 소개:** 16×16 칸에 마우스나 손가락으로 도트(점)를 찍어 작은 그림을 그리고, 완성하면 PNG 그림 파일로 저장하는 앱.

### 1-2. 휴대폰 화면 (폭이 좁을 때: 위에서 아래로 한 줄)

```
┌───────────────────────────┐
│ 픽셀 아트                  │
│ 16×16 칸에 도트를 찍어 그려요│
│ ┌───────────────────────┐ │
│ │                       │ │
│ │     16×16 그림판       │ │  ← 화면 폭 − 32px, 정사각형
│ │   (손가락으로 끌어 칠함) │ │
│ │                       │ │
│ └───────────────────────┘ │
│ [펜][지우개][채우기][스포이드]│  ← 도구 4개 한 줄
│ [↶][↷]   지금 색 ■ #FF3B30 │
│ ┌───────────────────────┐ │
│ │ ■ ■ ■ ■ ■ ■ ■ ■       │ │  ← 팔레트 8칸 × 2줄
│ │ ■ ■ ■ ■ ■ ■ ■ ■       │ │
│ │ [＋ 직접 고르기]        │ │
│ └───────────────────────┘ │
│ [격자선 ☑] [전체 지우기]    │
│ 저장 크기 [16배 ▾]          │
│ [      PNG로 저장       ]  │  ← 폭 가득 큰 버튼
└───────────────────────────┘
```

- 전체 폭: 최대 약 820px, 화면 가운데. **약 720px보다 좁으면** 휴대폰 배치(위→아래 한 줄)로 바뀐다.
- 그림판은 항상 **정사각형**, 칸 16×16 = 256칸.
- 그림판과 도구 상자는 각각 흰 카드(둥근 모서리 10px, 1px 테두리, 그림자 없음).

## 2. 기능 목록

### 필수 (첫 버전에 꼭 들어감)

| 번호 | 기능 | 설명 |
|---|---|---|
| F1 | 16×16 그림판 | 256칸. 빈 칸은 옅은 체크무늬로 보임 (투명이라는 뜻) |
| F2 | 마우스로 칠하기 | 누르면 한 칸, 누른 채 끌면 지나간 칸 모두 칠함 |
| F3 | 손가락으로 칠하기 | 톡 = 한 칸, 끌기 = 여러 칸. 그림판 위에서 끌 때 화면이 스크롤되지 않음 |
| F4 | 지우개 | 칸을 빈 칸(투명)으로 되돌림. 끌기로 여러 칸 지우기 가능 |
| F5 | 색상 팔레트 | 기본 색 16개(9번 D2). 누르면 그 색이 "지금 색"이 됨 |
| F6 | 지금 고른 색 표시 | 색 상자 + 색 코드(예: `#FF3B30`). 팔레트에서 고른 칸은 강조색 테두리 |
| F7 | 지금 도구 표시 | 펜/지우개 등 지금 고른 도구 버튼이 눌린 모양(강조색 테두리 + 굵게) |
| F8 | 전체 지우기 | 확인 창("정말 모두 지울까요?")에서 "확인"을 눌러야 지워짐 |
| F9 | PNG로 저장 | 그림을 PNG 파일로 내려받기 (3번에 자세히) |
| F10 | 기본/다크 모드 | 컴퓨터 설정(`prefers-color-scheme`)을 따라 자동. 화면 안 전환 버튼은 없음 |
| F11 | 휴대폰 대응 | 좌우 여백 16px, 가로 스크롤 없음, 버튼은 손가락으로 누르기 쉬운 크기(최소 40px) |

### 있으면 좋은 것 (9번 D1에서 결정. ★ = 첫 버전에 넣기 추천)

| 번호 | 기능 | 설명 | 난이도 | 추천 |
|---|---|---|---|---|
| S1 | 직접 색 고르기 | `<input type="color">`(브라우저 기본 색 고르기 창)로 팔레트에 없는 색 선택 | 하 | ★ |
| S2 | 채우기(페인트 통) | 누른 칸과 **같은 색으로 이어진** 칸을 한 번에 칠함 (위·아래·왼·오른쪽만 이어진 것으로 봄, 대각선 X) | 중 | ★ |
| S3 | 스포이드 | 그림판의 칸을 누르면 그 칸의 색이 "지금 색"이 됨. 고른 뒤 자동으로 펜 도구로 돌아감 | 하 | ★ |
| S4 | 되돌리기 / 다시하기 | 한 번의 "누르고-끌고-뗌"(한 획)을 한 단계로 셈. 최대 50단계. 전체 지우기·채우기도 되돌릴 수 있음 | 중 | ★ |
| S5 | 격자선 켜기/끄기 | 칸 사이 얇은 선을 보이거나 숨김 (PNG에는 어느 쪽이든 선이 안 들어감) | 하 | ★ |
| S6 | 작업 자동 저장 | 창을 닫았다 열어도 그리던 그림이 그대로 (7번) | 하 | ★ |
| S7 | 최근 쓴 색 | 직접 고른 색을 팔레트 아래에 최근 8개까지 보여 줌 | 하 | 다음 버전 |
| S8 | 단축키 | B 펜, E 지우개, G 채우기, I 스포이드, Ctrl+Z 되돌리기, Ctrl+Y(또는 Ctrl+Shift+Z) 다시하기 | 하 | 다음 버전 |

> 추천 이유: S1~S6은 각각 코드가 짧고 서로 잘 어울린다. 특히 S4(되돌리기)가 있으면 손가락 실수, 채우기 실수, 전체 지우기 실수를 모두 되살릴 수 있다. S7·S8은 화면이 복잡해지거나 휴대폰에선 쓸 일이 없어 다음으로 미룬다.

## 3. PNG 저장 방식

### 3-1. 결론

| 항목 | 추천 | 비고 |
|---|---|---|
| 만드는 방법 | 브라우저 기본 기능만 사용 (`canvas` + `toBlob`) | 외부 라이브러리·CDN **필요 없음** |
| 저장 크기 | 배율 고르기: 1배(16px) / 8배(128px) / **16배(256px, 기본)** / 32배(512px) | 9번 D3 |
| 빈 칸 | **투명**으로 저장 | 9번 D4. 체크무늬는 화면에만 보이고 파일에는 안 들어감 |
| 격자선 | 파일에 **넣지 않음** | 화면용 보조선일 뿐 |
| 흐려짐 방지 | 칸마다 정확한 정수 크기 사각형으로 칠하고, "부드럽게 처리" 끔 | 아래 3-3 |
| 파일 이름 | `pixel-art-20261103-153012.png` (날짜-시각) | 여러 번 저장해도 이름이 겹치지 않음 |

> 비유: 화면의 그림판은 "모눈종이 위 연필 스케치", PNG 저장은 "깨끗한 종이에 칸 크기를 정해 다시 옮겨 그려 인쇄하는 것". 모눈선(격자선)과 바탕 무늬(체크무늬)는 옮기지 않는다.

### 3-2. 저장 순서 (Build 담당 참고)

| 순서 | 하는 일 |
|---|---|
| 1 | 화면에 안 보이는 `canvas`(그림 그릴 수 있는 빈 종이)를 `16 × 배율` 크기로 새로 만든다. 예: 16배 → 256×256 |
| 2 | 처음엔 아무것도 칠하지 않음 → 전부 투명 |
| 3 | 256칸을 돌며 색이 있는 칸만 `(x×배율, y×배율)` 위치에 `배율×배율` 크기 사각형으로 칠한다 |
| 4 | `canvas.toBlob(..., "image/png")`로 PNG 파일 덩어리를 만든다 |
| 5 | 그 덩어리에 임시 주소(`URL.createObjectURL`)를 붙이고, `<a download="파일이름">`을 코드로 눌러 내려받게 한다 |
| 6 | 내려받기가 시작되면 임시 주소를 정리(`URL.revokeObjectURL`)한다 (조금 기다렸다가) |
| 7 | 화면에 "저장했어요" 안내를 2초쯤 보여 준다 (선택) |

### 3-3. 흐려지지 않게

| 원인 | 막는 방법 |
|---|---|
| 작은 그림을 크게 늘리면 브라우저가 경계를 뭉개서 부드럽게 만듦 | 늘리지 않고 **처음부터 큰 크기로 칸마다 사각형을 칠함** (3-2의 3번). 그래서 기본적으로 뭉개질 일이 없음 |
| 그래도 혹시 그림을 늘려 그리는 방식을 쓸 경우 | `ctx.imageSmoothingEnabled = false` (부드럽게 처리 끄기) |
| 칸 위치가 소수점이면 경계가 반투명해짐 | 위치·크기를 모두 **정수**로 (배율이 정수라 자동으로 정수) |
| 화면의 그림판도 칸 경계가 흐릿해 보일 수 있음 | 그림판 칸 크기를 정수 px로 맞춤 (6-1) |

### 3-4. 더블클릭(file://)으로 열었을 때

| 항목 | 판단 |
|---|---|
| `canvas.toBlob` | 동작함. 바깥 그림을 불러오지 않고 앱이 직접 칠한 그림이라 브라우저 보안에 걸리지 않음 |
| 데스크톱 크롬·엣지·파이어폭스 | `<a download>` + 임시 주소로 내려받기 동작 (Review 담당이 실제 확인) |
| 휴대폰(아이폰 사파리) | 내려받기 방식이 브라우저마다 달라 **확인 필요**. 안 될 때를 대비한 대안: 그림을 새 탭에 띄우고 "그림을 길게 눌러 저장하세요" 안내 |
| `toBlob`을 못 쓰는 옛 브라우저 | `toDataURL`(그림을 긴 글자로 바꾸는 방식)로 대신 |

## 4. 파일 구조

모든 파일은 `apps/pixel-art/` 안에 있고, 블로그의 다른 파일(`src/style.css` 등)이나 다른 앱(`game-2048`)은 **불러 쓰지 않는다** (색 값은 복사해서 씀).

| 파일 | 역할 | 비유 | 공개 사이트에 올림? |
|---|---|---|---|
| `index.html` | 화면의 뼈대: 제목, 그림판 자리, 도구·팔레트·버튼 | 건물의 골조 | O |
| `style.css` | 색·크기·모서리·체크무늬·다크 모드·휴대폰 배치 | 인테리어 | O |
| `app.js` | 그림 데이터, 칠하기·지우기·채우기, 마우스·터치 처리, 되돌리기, PNG 저장, 자동 저장 | 작업실 관리인 | O |
| `preview.svg` | 블로그 첫 화면 카드용 미리보기 그림 (Build 담당이 만듦) | 가게 간판 | O |
| `spec.md` | 이 계획서 | 설계도 | X |
| `review.md` | Review 담당의 검사 결과 (나중에 생김) | 검수 보고서 | X |
| `지침/` | 담당별 작업 지침 | 업무 지시서 | X |
| `app.json` | 블로그 카드 정보 (Embed 단계에서 만듦) | 간판 문구 | (빌드가 읽음) |

- 외부 라이브러리·CDN·외부 글꼴 **사용 안 함** (PNG 저장도 브라우저 기본 기능으로 충분).
- `index.html`을 **더블클릭해서 바로 열려도** 동작해야 한다 → `fetch`, `type="module"` 쓰지 않음. `<script src="app.js">`를 `</body>` 바로 앞에 둔다.
- 아이콘(펜·지우개·통·스포이드·되돌리기)은 얇은 선 SVG를 `index.html` 안에 직접 적는다 (그림 파일 따로 없음). 각 버튼에 글자 이름도 함께 표시하거나 `aria-label`을 단다.

### 4-1. `preview.svg` 내용 (Build 담당)

| 항목 | 내용 |
|---|---|
| 그림 | 16×16 도트로 그린 작은 그림 (예: 하트 또는 웃는 얼굴) + 아래에 팔레트 색 칩 몇 개 |
| 크기 | 가로세로 비율은 2048의 `preview.svg`와 같게 맞춘다 (카드 모양 통일) — 실제 비율은 Build 담당이 2048 파일을 보고 확인 |
| 바탕 | 블로그 기본 모드 색(바탕 `#EEEFF2`, 카드 `#FFFFFF`) |
| 도트 경계 | 흐려지지 않게 `shape-rendering="crispEdges"` |

### 4-2. `app.js` 안의 구성 (권장)

| 묶음 | 하는 일 |
|---|---|
| 상태 | 그림 데이터(256칸), 지금 색, 지금 도구, 격자선 켜짐 여부, 되돌리기 기록 |
| 그림 함수 | 칸 칠하기, 지우기, 채우기, 칸 색 읽기 — **화면과 상관없이 데이터만 바꿈** |
| 그리기 함수 | 데이터를 보고 그림판 화면을 다시 칠함 |
| 입력 처리 | 마우스·손가락(포인터 이벤트), 도구·팔레트·버튼 |
| 되돌리기 | 한 획 전·후 그림을 기록 |
| PNG 저장 | 3번 순서대로 |
| 자동 저장 | 7번. 모든 읽기·쓰기 `try/catch` |

## 5. 화면 동작 설계

### 5-1. 핵심 생각: "장부"와 "게시판"

| 개념 | 쉬운 설명 |
|---|---|
| 그림 데이터(장부) | **256칸짜리 색 목록**. 왼쪽 위부터 오른쪽으로, 한 줄 다 가면 다음 줄. 빈 칸은 `null`(없음), 칠한 칸은 `"#FF3B30"` 같은 색 코드 |
| 칸 번호 | `번호 = 줄 × 16 + 칸`. 예: 맨 왼쪽 위 = 0, 첫 줄 맨 오른쪽 = 15, 둘째 줄 첫 칸 = 16, 맨 오른쪽 아래 = 255 |
| 그리기(게시판) | 장부를 보고 그림판 화면을 칠하는 일 |
| 원칙 | **화면을 직접 고치지 않고, 장부를 고친 뒤 → 다시 그린다** |

> 비유: 엑셀 시트에 16행×16열 표가 있고, 셀마다 "무슨 색인지"만 적혀 있다. 화면은 그 표를 보고 셀 배경색을 칠한 것뿐이다. PNG 저장도, 자동 저장도 모두 이 표 하나만 보면 된다.

### 5-2. 그림판을 화면에 그리는 방법

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 칸 256개를 `<div>`로 깔고 배경색 바꾸기 | 이해하기 쉬움, 격자선·체크무늬를 CSS로 쉽게 | 칸이 많지만 256개는 충분히 가벼움 | **추천** |
| 화면에도 `canvas` 하나로 그리기 | 빠름 | 체크무늬·격자선·선명도를 직접 계산해야 함 | Build 담당이 더 낫다고 판단하면 사용 가능 |

- 체크무늬는 그림판 **바탕**에 CSS로 깔고, 칠한 칸만 색을 덮는다 → 빈 칸은 저절로 체크무늬로 보임.
- 칸에 색이 바뀔 때는 그 칸만 고쳐도 되고, 전체를 다시 그려도 된다(256칸이라 빠름).

### 5-3. 칠하기 흐름 (한 획)

```
[누름 (마우스 버튼 / 손가락 닿음)]
        ↓
 누른 위치 → 어느 칸인지 계산 (그림판 밖이면 무시)
        ↓
 "획 시작" 기록 (되돌리기용: 지금 그림 복사)
        ↓
 도구에 따라:
   펜 → 그 칸을 지금 색으로      지우개 → 그 칸을 빈 칸으로
   채우기 → 이어진 같은 색 칸 모두 칠하고 끝   스포이드 → 그 칸 색을 지금 색으로, 펜으로 돌아가고 끝
        ↓
[끌기 (누른 채 움직임)]  ← 펜·지우개만
 새 위치의 칸 계산 → 바로 전 칸과 새 칸 사이를 **직선으로 이어** 그 사이 칸도 모두 칠함
        ↓
[뗌 / 취소(전화 옴 등)]
 그림이 실제로 바뀌었으면 되돌리기 기록 1단계 추가 → 자동 저장
```

### 5-4. 위치 → 칸 계산, 빠지는 칸 막기

| 항목 | 방법 |
|---|---|
| 칸 계산 | 그림판의 화면 위치·크기(`getBoundingClientRect`)를 구해서 `칸 = 내림((손 x − 판 왼쪽) ÷ 칸 크기)`, 줄도 같은 방식. 0~15 밖이면 무시 |
| 빨리 끌 때 빠지는 칸 | 브라우저는 움직임을 띄엄띄엄 알려 준다 → **바로 전 칸과 지금 칸 사이를 직선으로 잇는 칸들**(브레젠험 선 긋기 방식)을 모두 칠함 |
| 같은 칸 반복 | 바로 전과 같은 칸이면 아무것도 안 함 (불필요한 다시 그리기 방지) |
| 그림판 밖으로 나갔다 들어옴 | 누른 채 밖으로 나가도 획은 계속됨. 밖에 있는 동안은 칠하지 않고, 다시 들어오면 이어 칠함 |
| 판 밖에서 뗌 | 획이 정상 종료됨 (마우스 잡기 `setPointerCapture` 사용) |

### 5-5. 입력 방식

- 마우스·펜·손가락을 한 번에 다루는 **포인터 이벤트**(`pointerdown` / `pointermove` / `pointerup` / `pointercancel`)를 쓴다.
- 마우스는 **왼쪽 버튼만** 칠함. 오른쪽 클릭은 그림판 위에서 메뉴가 뜨지 않게 막고 아무것도 안 함.
- 손가락 두 개가 닿으면 두 번째 손가락은 무시 (처음 닿은 손가락만 따라감).
- 그림판 위에서 글자 선택·그림 끌기가 일어나지 않게 막는다 (`user-select: none`, 끌기 기본 동작 막기).

### 5-6. 되돌리기 / 다시하기 (S4)

| 항목 | 방법 |
|---|---|
| 기록 단위 | 한 획 = 1단계 (채우기 1번, 전체 지우기 1번도 각각 1단계) |
| 기록 내용 | 그 단계 **전의 그림 전체**(256칸 목록 복사). 256칸이라 50개 쌓여도 가벼움 |
| 최대 | 50단계. 넘치면 가장 오래된 것부터 버림 |
| 다시하기 | 되돌린 뒤 **새로 칠하면** 다시하기 기록은 사라짐 (일반 프로그램과 같음) |
| 버튼 상태 | 되돌릴 게 없으면 되돌리기 버튼 흐리게(누를 수 없음). 다시하기도 같음 |
| 바뀐 게 없는 획 | 이미 같은 색인 칸을 칠한 경우 등은 기록하지 않음 |
| 저장 | 되돌리기 기록은 자동 저장하지 **않음** (새로 열면 기록 없이 시작) |

### 5-7. 채우기 (S2)

- 누른 칸의 색(빈 칸이면 "빈 칸")과 **똑같은** 칸 중, 위·아래·왼·오른쪽으로 이어진 칸을 모두 지금 색으로 바꾼다.
- 누른 칸이 이미 지금 색이면 아무것도 안 함.
- 빈 그림판에서 채우기 → 256칸 전부 칠해짐.
- 방식: "할 일 목록"에 누른 칸을 넣고, 하나씩 꺼내 주변 4칸을 검사하는 방식(되부름 함수 대신 목록 사용 → 멈춤 걱정 없음).

### 5-8. 색상

**화면 색 (블로그 색 그대로, CSS 변수: 기본은 `:root`, 다크는 `@media (prefers-color-scheme: dark)`)**

| 글자 | `#1D1D1F` | `#ECECEE` |

**빈 칸(투명) 체크무늬**

### 6-1. 그림판 크기 맞춤

| 항목 | 규칙 |
|---|---|
| 좌우 여백 | 16px |

| 크기 다시 계산 | 화면 크기가 바뀔 때(가로·세로 돌리기 포함) 다시 계산 |
| 가장 작은 화면(320px) | 칸 약 16px. 손가락으로도 칠할 수 있는 크기(끌기로 칠하므로 충분) |
| 가로 스크롤 | 없음 (375px·320px 폭에서 확인) |

> CSS만으로 맞추기 어려우면 `app.js`에서 크기를 계산해 넣어도 된다 (Build 담당 판단).

### 6-2. 손가락 끌기 판정

| 상황 | 동작 |
|---|---|
| 톡 치기 | 그 칸 한 칸 칠함 |
| 누른 채 끌기 | 지나간 칸 모두 칠함 (5-4의 직선 잇기로 빠짐 없이) |
| 칸 경계 위에 손가락 | 손가락의 **중심 한 점**이 있는 칸 하나만 (손가락 면적 전체를 칠하지 않음) |
| 두 손가락 | 처음 손가락만 인정, 두 번째는 무시 |
| 전화·알림으로 끊김(`pointercancel`) | 그때까지 칠한 것은 남기고 획을 정상 종료 |

### 6-3. 그릴 때 화면 스크롤 막기

| 방법 | 설명 |
|---|---|
| 그림판에 `touch-action: none` | 그림판 위에서는 브라우저가 손가락 움직임을 스크롤·확대로 쓰지 않음 |
| 보조: 터치 이동 중 기본 동작 막기 | 위 방법이 안 먹는 옛 브라우저용 (`touchmove`에 `preventDefault`, 등록 시 `passive: false`) — 필요 여부 **확인 필요** |
| 그림판 밖 | 평소처럼 스크롤·확대 가능 (페이지 전체를 막지 않음) |
| 두 번 톡 확대 | 그림판·버튼에서 두 번 빨리 눌러도 화면이 확대되지 않게 (`touch-action: manipulation`을 버튼에) |
| 길게 누르기 메뉴 | 그림판을 길게 눌러도 "복사/저장" 메뉴가 뜨지 않게 (`-webkit-touch-callout: none`) |

## 7. 저장 (localStorage) — S6 자동 저장

> `localStorage` = 브라우저 안의 작은 메모장. 창을 닫아도 남는다. 다른 사람·다른 기기와는 공유되지 않는다.

| 저장 이름(키) | 내용 | 언제 쓰나 |
|---|---|---|
| `pixelArt.v1` | `{ pixels: [256칸 색 목록], color: "#000000", grid: true, scale: 16 }` | 획이 끝날 때, 채우기·전체 지우기·되돌리기·다시하기 후, 색·격자선·저장 크기를 바꿀 때 |

- 이름 앞에 `pixelArt.`을 붙여 블로그·2048 저장값과 섞이지 않게 한다. 끝의 `v1`은 "1판 형식"이라는 뜻(나중에 형식이 바뀌면 `v2`로).
- 끄는 중(획 진행 중)에는 저장하지 않고 **획이 끝날 때 한 번만** 저장 (느려지지 않게).
- **모든 읽기·쓰기는 `try/catch`로 감싼다.** 저장이 막힌 환경(시크릿 창, 설정 차단)에서는 저장만 안 되고 그리기는 정상. 이때 화면 아래 안내를 "자동 저장을 쓸 수 없어요"로 바꿔 보여 준다(선택).
- 읽은 값 검사 — 하나라도 이상하면 **그 값은 버리고 기본값으로 시작**:

| 검사 | 이상한 예 | 처리 |
|---|---|---|
| `pixels`가 목록이고 길이가 정확히 256 | 길이 100, 글자 | 빈 그림판 |
| 각 칸이 `null` 또는 `#` + 16진수 6자리 | `"red"`, `"<script>"`, 숫자 | 그 칸은 빈 칸으로 (또는 전체 버림 — Build 담당 판단) |
| `color`가 `#` + 16진수 6자리 | `"abc"` | 검정 |
| `scale`이 1·8·16·32 중 하나 | `999` | 16 |
| `grid`가 참/거짓 | `"yes"` | 켜짐 |

> 색 코드 형식을 꼭 검사하는 이유: 저장값은 누구나 개발자 도구로 바꿀 수 있다. 검사 없이 화면에 넣으면 이상한 값이 화면을 깨뜨릴 수 있다. 색은 `element.style.backgroundColor = 색`으로만 넣고, `innerHTML`에 넣지 않는다.

## 8. Review 담당 검증 체크리스트

### 8-1. 칠하기·지우기

- [ ] 마우스로 한 번 누르면 정확히 **누른 칸 하나**만 칠해짐 (옆 칸 X)
- [ ] 칸 경계 근처(선 바로 위)를 눌러도 한 칸만 칠해짐
- [ ] 마우스로 **빠르게** 대각선·가로·세로로 끌어도 지나간 길에 **빠진 칸이 없음**
- [ ] 누른 채 그림판 밖으로 나갔다가 다시 들어와도 이어서 칠해짐, 밖에서 떼도 획이 끝남(이후 마우스를 움직여도 칠해지지 않음)
- [ ] 맨 끝 칸(0번·15번·240번·255번) 모두 칠해짐, 그림판 테두리 바깥을 눌러도 아무 일 없음
- [ ] 오른쪽 클릭: 메뉴가 안 뜨고 칠해지지도 않음
- [ ] 지우개: 한 칸·끌기 모두 빈 칸(체크무늬)으로 돌아감
- [ ] 팔레트 칩을 누르면 지금 색 표시·고른 칩 테두리가 바뀜, 도구가 지우개였다면 펜으로 바뀜(또는 지금 색만 바뀜 — 구현 방식 기록)
- [ ] 전체 지우기: "취소" 누르면 그대로, "확인" 누르면 모두 빈 칸

### 8-2. 선택 기능 (첫 버전에 넣은 것만)

- [ ] 직접 색 고르기: 고른 색으로 칠해짐, 색 코드 표시 바뀜
- [ ] 채우기: 빈 그림판에서 누르면 256칸 모두 칠해짐
- [ ] 채우기: 닫힌 테두리 안쪽만 채워짐, **대각선으로만 이어진 칸으로는 새지 않음**
- [ ] 채우기: 누른 칸이 이미 지금 색이면 아무 변화 없고 되돌리기 기록도 안 늘어남
- [ ] 스포이드: 칠한 칸 → 그 색이 지금 색이 되고 펜으로 돌아감. 빈 칸 → 지우개로 바뀌거나 아무 일 없음(구현 방식 기록)
- [ ] 되돌리기: 끌기 한 획이 **한 번에** 통째로 되돌아감 (한 칸씩 X)
- [ ] 되돌리기: 채우기·전체 지우기도 되돌려짐
- [ ] 되돌린 뒤 다시하기 → 원래대로. 되돌린 뒤 새로 칠하면 다시하기 버튼이 흐려짐
- [ ] 51번 이상 칠한 뒤 되돌리기는 50번까지만 되고 오류 없음
- [ ] 되돌릴 게 없을 때 버튼이 흐리고 눌러도 오류 없음
- [ ] 격자선 끄기·켜기 동작, 끈 상태에서도 칸 계산이 정확함

### 8-3. PNG 저장

- [ ] 저장 버튼 → 파일이 내려받아짐, 이름이 `pixel-art-날짜-시각.png` 형식
- [ ] 배율별 실제 그림 크기: 1배 16×16, 8배 128×128, 16배 256×256, 32배 512×512 (그림 파일 속성 또는 브라우저로 열어 확인)
- [ ] 빈 칸이 **투명**으로 저장됨 (어두운 바탕 위에 띄워 보면 바탕이 비쳐 보임). 체크무늬가 파일에 들어가지 않음
- [ ] 격자선이 파일에 들어가지 않음 (격자선 켠 상태에서 저장해 확인)
- [ ] 크게 확대해 봐도 칸 경계가 **흐리지 않고 딱 떨어짐** (반투명 테두리 없음)
- [ ] 저장한 그림의 색·위치가 화면과 똑같음 (예: 왼쪽 위 0번 칸만 빨강으로 칠해 저장 → 그림 왼쪽 위만 빨강), 위아래·좌우 뒤집힘 없음
- [ ] 빈 그림판을 저장해도 오류 없음 (완전 투명 그림)
- [ ] `index.html` **더블클릭(file://)** 으로 연 상태에서도 저장 동작 (크롬 또는 엣지)
- [ ] 휴대폰(가능하면 실제 기기 또는 휴대폰 흉내 모드)에서 저장 시 어떻게 되는지 기록 — 안 되면 대안(새 탭 + 길게 눌러 저장 안내) 동작 확인 → **확인 필요**

### 8-4. 휴대폰·터치

- [ ] 375px·320px 폭에서 **가로 스크롤 없음**, 그림판이 잘리지 않고 정사각형
- [ ] 칸 크기가 정수 px (흐릿한 격자 없음) — 개발자 도구로 그림판 폭이 16의 배수인지 확인
- [ ] 손가락(또는 터치 흉내)으로 톡 = 한 칸, 끌기 = 여러 칸, 빠진 칸 없음
- [ ] 그림판 위에서 끌 때 **페이지가 스크롤되지 않음**, 그림판 밖에서는 스크롤 정상
- [ ] 그림판을 길게 눌러도 메뉴가 안 뜸, 두 번 톡 쳐도 확대 안 됨
- [ ] 두 손가락이 닿아도 이상하게 칠해지지 않음
- [ ] 팔레트 8칸 × 2줄, 칩·버튼이 손가락으로 누르기 충분한 크기
- [ ] 가로로 돌렸을 때(가로 화면) 그림판이 화면 높이 안에 들어옴
- [ ] 화면 크기를 바꾸면 그림판 크기가 다시 맞춰지고, 그 뒤에도 칸 계산이 정확

### 8-5. 화면·저장·보안

- [ ] 기본/다크 모드 둘 다: 체크무늬가 보이지만 그림보다 튀지 않음, 흰색 칸과 빈 칸 구분됨, 검정 칸과 다크 바탕 구분됨
- [ ] 두 모드 모두 글자·버튼이 잘 읽힘 (대비 확인), 고른 칩·고른 도구가 눈에 띔
- [ ] 자동 저장: 그린 뒤 새로 고침 → 그림·지금 색·격자선·저장 크기가 그대로
- [ ] 시크릿 창 또는 저장 차단 상태에서도 오류 없이 그리기·PNG 저장 동작 (개발자 도구 콘솔에 빨간 오류 없음)
- [ ] 저장값을 일부러 이상하게 바꿔도(`pixelArt.v1`에 `"abc"`, 길이 100짜리 목록, 칸에 `"<img src=x onerror=alert(1)>"`) 앱이 정상 시작, 경고창 안 뜸
- [ ] 키보드만으로 도구·팔레트·버튼을 Tab으로 이동·Enter로 누를 수 있음, 포커스 테두리가 보임
- [ ] 외부 파일(CDN·외부 글꼴·블로그 다른 파일·2048 파일)을 불러오지 않음
- [ ] `fetch`, `type="module"`을 쓰지 않음
- [ ] 코드에 한글 주석이 짧게 달려 있음
- [ ] `preview.svg`가 열리고 도트 경계가 선명함
- [ ] 개인 정보·회사 정보·PC 경로가 파일에 없음 (공개 저장소)
