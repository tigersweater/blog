# Plan 담당 지침: 픽셀 아트 에디터

## 할 일
픽셀 아트 에디터 웹앱의 **계획서** `apps/pixel-art/spec.md`를 작성한다. 코드는 만들지 않는다.

## 사용자 요청 (원문 요지)
- 16×16 격자에 도트를 찍어 그림을 그린다
- 완성하면 **PNG로 저장**할 수 있다
- **색상 팔레트**를 넣는다

## 지켜야 할 규칙 (프로젝트 CLAUDE.md에서 발췌)
- HTML, CSS, JavaScript만. 프레임워크 금지. 외부 라이브러리는 최소화(CDN은 허용되지만, 없이 만드는 것을 우선 검토. PNG 저장은 브라우저 기본 기능 `canvas.toBlob`/`toDataURL`로 가능한지 검토)
- 모든 파일은 `apps/pixel-art/` 안에서 자체 완결
- 휴대폰에서도 쓸 수 있어야 함: 좌우 여백 16px, 가로 스크롤 없음, **터치로 그리기 가능**(손가락으로 끌어서 여러 칸 칠하기, 그릴 때 화면 스크롤 막기)
- 디자인은 가능하면 블로그와 같은 색·모서리 규칙 (아래)
- 기본/다크 모드: `prefers-color-scheme`을 따름 (블로그 첫 화면 카드는 미리보기 그림 + 누르면 앱 페이지로 이동하는 방식, iframe 아님)
- `localStorage`를 쓰면 읽기/쓰기는 `try/catch`
- `index.html` 더블클릭(file://)으로 열어도 동작해야 함: `fetch`, `type="module"` 쓰지 않음. file://에서 PNG 저장(다운로드)이 되는지도 고려
- 코드에 한글 주석을 짧게
- 사용자는 코딩 초보 → spec.md는 쉬운 한국어, 표 활용

- 공개 사이트에는 앱 파일만 올라가고, 카드용 미리보기 그림 `preview.svg`를 Build 담당이 함께 만든다. 카드 정보 `app.json`은 Embed 단계에서 만든다 → spec의 파일 구조에 `preview.svg` 포함
- 블로그 카드·복사 방식은 이미 정해져 있으므로 D6~D9 같은 블로그 연결 결정은 다시 묻지 않는다

## spec.md에 담을 내용
1. 한 줄 소개와 완성 화면 설명 (글로 그린 배치도. 데스크톱·휴대폰 배치가 다르면 둘 다)
2. 기능 목록: 필수 / 있으면 좋은 것 구분
   - 필수 후보: 16×16 격자, 클릭·끌기로 칠하기, 터치로 칠하기, 지우개, 색상 팔레트(기본 색 몇 개), 지금 고른 색 표시, 전체 지우기(확인 후), PNG 저장
   - 있으면 좋은 것 후보: 직접 색 고르기(`<input type="color">`), 채우기(페인트 통), 스포이드, 되돌리기/다시하기, 격자선 켜기/끄기, 작업 자동 저장, 최근 쓴 색
3. PNG 저장 방식: 저장 크기(16×16 그대로면 너무 작음 → 배율 선택 또는 고정 배율 등 선택지), 빈 칸은 투명으로 저장할지, 파일 이름, 흐려지지 않게(이미지 부드럽게 처리 끄기)
4. 파일 구조와 각 파일 역할 (`index.html`, `style.css`, `app.js`(또는 적당한 이름), `preview.svg`)
5. 화면 동작 설계: 그림 데이터를 어떻게 저장하고 그리는지 쉬운 말로 (예: 256칸짜리 색 목록)
6. 휴대폰 대응: 격자 크기 맞춤, 손가락 끌기 판정, 스크롤 막기, 팔레트 배치
7. 저장(localStorage)을 쓴다면 방식
8. Review 담당이 확인할 **검증 항목 체크리스트** (예: 칸 경계에서 끌 때 빠지는 칸 없음, 저장한 PNG가 실제로 16×16 배율대로·투명 배경으로 나오는지, 작은 화면에서 격자가 잘리지 않음 등)
9. **사용자가 정해야 할 것** 목록 (선택지와 추천안 함께). 예: 있으면 좋은 것 중 첫 버전에 넣을 것, 팔레트 구성(색 개수·종류), PNG 저장 크기, 빈 칸 투명 여부, 자동 저장 여부
