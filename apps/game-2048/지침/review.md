# Review 담당 지침: 2048 게임

## 할 일
Build 담당이 만든 2048 게임을 **검사**하고 결과를 `apps/game-2048/review.md`로 쓴다. 고치는 것은 Build 담당이 한다 → 당신은 **코드를 고치지 않는다.**

## 검사 대상
`apps/game-2048/`의 `index.html`, `style.css`, `game.js`, `preview.svg`
기준 문서: `apps/game-2048/spec.md` (특히 8번 체크리스트, 10번 결정 사항)

## 검사 방법
1. **코드 읽기**: 규칙(spec 3번), 보안(`innerHTML`에 외부 입력 없음, 외부 주소 호출 없음), `localStorage`가 모두 `try/catch`인지, `fetch`/`type="module"` 없음(더블클릭 실행 가능), 한글 주석, 개인 정보·PC 경로 없음
2. **규칙 시험 (Node)**: `game.js`의 합치기 함수를 Node에서 불러 spec 8-1의 예시를 모두 시험. 방법은 자유(예: 임시 폴더에 시험 스크립트를 만들고 `vm`으로 game.js를 읽어 실행). 시험 파일은 프로젝트 폴더 밖 임시 폴더에 두고 끝나면 지운다
3. **브라우저 시험**: 내장 브라우저 도구(`mcp__Claude_Browser__*`)를 쓴다
   - 프로젝트 폴더 밖 임시 폴더에 Node 정적 서버 스크립트를 만들어 `apps/game-2048`를 **포트 4322**로 띄운다 (4321은 블로그 미리보기가 쓰는 중이니 건드리지 말 것)
   - 확인: 첫 화면(타일 2개), 방향키·WASD로 이동, 점수 증가, 새 게임, 새로고침 후 하던 판·최고 점수 유지, 게임 오버/2048 안내(필요하면 `localStorage`에 상태를 넣어 재현), 다크 모드(`resize_window`의 colorScheme), 휴대폰 너비 375px·320px에서 가로 스크롤 없음·판이 잘리지 않음, 콘솔 오류 없음
   - 스와이프는 도구로 완전히 재현하기 어려우면 코드 검토로 대신하고 그렇게 적는다
   - 끝나면 서버를 끄고, 창 크기를 `preset: "desktop"`으로 되돌린다
4. `preview.svg`가 브라우저에서 제대로 보이는지

## review.md에 쓸 내용
- 맨 위: **결론** (통과 / 수정 필요) 한 줄
- 표: 검사 항목 | 결과(✅/❌/△) | 메모 — spec 8번 체크리스트 순서대로
- **수정 필요 목록**: 번호, 문제, 재현 방법, 어느 파일 어디쯤, 고치는 방향 (심각도: 높음/보통/낮음)
- 확인하지 못한 것과 이유
- 쉬운 한국어로 (사용자는 코딩 초보)
