# Plan 담당 지침: 2048 게임

## 할 일
2048 웹앱의 **계획서** `apps/game-2048/spec.md`를 작성한다. 코드는 만들지 않는다.

## 사용자 요청 (원문 요지)
- 2048 게임: 방향키로 숫자 타일을 밀어서 같은 숫자를 합치는 퍼즐
- 점수판을 넣을 것

## 지켜야 할 규칙 (프로젝트 CLAUDE.md에서 발췌)
- HTML, CSS, JavaScript만 사용. 프레임워크(React 등) 금지. 외부 라이브러리는 최소화(CDN은 허용되지만 이 게임은 없이 만드는 것을 우선 검토)
- 모든 파일은 `apps/game-2048/` 안에서 자체 완결 (블로그의 다른 파일을 불러 쓰지 않음)
- 휴대폰에서도 쓸 수 있어야 함: 좌우 여백 16px, 가로 스크롤 없음, **터치(스와이프)로 조작 가능**
- 디자인은 가능하면 블로그와 같은 색·모서리 규칙 (아래 "디자인 참고")
- 기본 모드 / 다크 모드 둘 다 보기 좋게. 블로그처럼 `prefers-color-scheme`을 따르고, 블로그 첫 화면에 iframe으로 넣을 수도 있음을 고려
- `localStorage`를 쓰면 읽기/쓰기를 `try/catch`로 감쌀 것 (저장이 막혀도 게임은 정상 동작)
- 코드에는 한글 주석을 짧게
- 사용자는 코딩 초보 → spec.md는 쉬운 한국어로, 전문 용어는 풀어서, 표 활용

| 글자 | #1D1D1F | #ECECEE |

- 타일 숫자별 색은 새로 정해도 됨 (두 모드 모두 글자가 잘 읽히게)

## spec.md에 담을 내용
1. 한 줄 소개와 완성 화면 설명 (글로 그린 화면 배치 그림 포함)
2. 기능 목록: 필수 / 있으면 좋은 것 구분
   - 필수 후보: 4×4 판, 시작 타일 2개, 방향키·WASD·스와이프 조작, 합치기 규칙(한 번 움직일 때 한 타일은 한 번만 합쳐짐), 새 타일(2가 90%, 4가 10%), 현재 점수·최고 점수, 새 게임 버튼, 게임 오버·2048 달성 안내
   - 있으면 좋은 것 후보: 타일 이동·합치기 애니메이션, 되돌리기, 2048 달성 후 계속하기 등
3. 게임 규칙 정리 (점수 계산: 합쳐진 타일의 숫자만큼 점수 증가)
4. 파일 구조 (`index.html`, `style.css`, `game.js` 등) 와 각 파일의 역할
5. 화면 동작 설계: 게임 상태를 어떻게 저장하고 그리는지 쉬운 말로
6. 휴대폰 대응: 스와이프 판정 방식, 스와이프 중 화면 스크롤 막기, 작은 화면 크기 맞춤
7. 저장: 최고 점수(필요하면 진행 중 게임도) localStorage 저장 방식
8. Review 담당이 확인할 **검증 항목 체크리스트** (합치기 규칙의 까다로운 경우 예: `2 2 2 2` → `4 4`, `2 2 4` 왼쪽 → `4 4`, 움직임이 없으면 새 타일이 생기지 않음 등)
9. **사용자가 정해야 할 것** 목록 (선택지와 추천안 함께). 예:
   - 2048 달성 후 계속하기 여부, 되돌리기 여부, 애니메이션 여부
   - 블로그 첫 화면 카드에 넣을 것: 미리보기 이미지 vs iframe
   - 웹앱 카드 위치: 글 목록 위 별도 영역 vs 글 목록과 섞기
   - spec.md·review.md·지침 폴더를 공개 사이트에도 올릴지
