## 1. 한 줄 소개와 완성 화면

**한 줄 소개:** 방향키(또는 휴대폰에서 손가락으로 밀기)로 숫자 타일을 밀어, 같은 숫자끼리 합쳐 2048을 만드는 퍼즐 게임.

### 완성 화면 (글로 그린 배치도)

```
┌─────────────────────────────────────────┐   ← 바탕(캔버스 색)
│                                         │
│  2048                  ┌──────┐┌──────┐ │   ← 제목(굵게) / 점수 상자 2개
│                        │ 점수 ││ 최고 │ │
│                        │ 1240 ││ 5320 │ │
│                        └──────┘└──────┘ │
│                                         │
│  같은 숫자를 합쳐 2048을!   [ 새 게임 ] │   ← 설명 한 줄(보조 글자) / 버튼
│                                         │
│  ┌───────────────────────────────────┐  │   ← 게임판 (카드, 둥근 모서리 10px)
│  │ ┌────┐ ┌────┐ ┌────┐ ┌────┐      │  │
│  │ │  2 │ │    │ │    │ │  4 │      │  │
│  │ └────┘ └────┘ └────┘ └────┘      │  │
│  │ ┌────┐ ┌────┐ ┌────┐ ┌────┐      │  │
│  │ │    │ │  8 │ │    │ │    │      │  │   ← 4×4 칸
│  │ └────┘ └────┘ └────┘ └────┘      │  │
│  │ ┌────┐ ┌────┐ ┌────┐ ┌────┐      │  │
│  │ │    │ │    │ │ 16 │ │    │      │  │
│  │ └────┘ └────┘ └────┘ └────┘      │  │
│  │ ┌────┐ ┌────┐ ┌────┐ ┌────┐      │  │
│  │ │  2 │ │    │ │    │ │ 32 │      │  │
│  │ └────┘ └────┘ └────┘ └────┘      │  │
│  └───────────────────────────────────┘  │
│                                         │
│  조작: 방향키 · WASD · 화면 밀기         │   ← 도움말 (보조 글자, 작게)
└─────────────────────────────────────────┘
```

게임이 끝나거나 2048을 만들면 **게임판 위에 반투명 막**이 덮이고 안내 문구가 뜬다.

```
  ┌───────────────────────────────────┐
  │                                   │
  │          게임 끝!                  │
  │      최종 점수 1240               │
  │        [ 다시 하기 ]              │
  │                                   │
  └───────────────────────────────────┘
```

- 전체 폭: 최대 약 480px, 화면 가운데 정렬. 휴대폰에서는 화면 폭 − 좌우 여백 16px씩.
- 게임판은 항상 **정사각형**.

## 2. 기능 목록

### 필수 (첫 버전에 꼭 들어감)

| 번호 | 기능 | 설명 |
|---|---|---|
| F1 | 4×4 게임판 | 칸 16개 |
| F2 | 시작 타일 2개 | 새 게임 시작 시 빈 칸 중 무작위 2곳에 타일 생성 |
| F3 | 키보드 조작 | 방향키 ←↑→↓, WASD (대·소문자 모두, 한글 입력 상태 확인 필요 → 6번 참고) |

| F6 | 새 타일 | 판이 실제로 움직였을 때만 빈 칸 1곳에 새 타일. 2가 90%, 4가 10% |

| F9 | 새 게임 버튼 | 누르면 판·점수 초기화 (최고 점수는 유지) |
| F10 | 게임 오버 안내 | 빈 칸도 없고 합칠 수도 없으면 "게임 끝!" + 다시 하기 |
| F11 | 2048 달성 안내 | 처음 2048 타일이 생기면 "2048 달성!" 안내 |
| F12 | 기본/다크 모드 | 컴퓨터 설정(`prefers-color-scheme`)을 따라 자동 |
| F13 | 휴대폰 대응 | 좌우 여백 16px, 가로 스크롤 없음, 밀기 중 화면 스크롤 막기 |

## 3. 게임 규칙 정리

### 3-1. 한 번 움직일 때 일어나는 일 (순서대로)

| 순서 | 하는 일 |
|---|---|
| 1 | 누른 방향으로 모든 타일을 끝까지 민다 (빈 칸 없이 붙임) |
| 2 | 미는 방향 **쪽 끝부터** 차례로 보면서, 같은 숫자 두 개가 붙어 있으면 하나로 합친다 (숫자 ×2) |
| 3 | 이미 합쳐져 생긴 타일은 이번 이동에서 **다시 합쳐지지 않는다** |
| 4 | 합친 뒤 생긴 빈 틈을 다시 당겨 붙인다 |
| 5 | 판이 **조금이라도 달라졌으면** 빈 칸 하나에 새 타일(2: 90%, 4: 10%)을 놓는다. 달라진 게 없으면 아무 일도 안 일어남 (새 타일 X, 점수 변화 X) |
| 6 | 2048 타일이 처음 생겼는지 확인 → 안내 |
| 7 | 더 움직일 수 있는지 확인 → 못 움직이면 게임 오버 |

> 비유: 줄 선 사람들을 한쪽 벽으로 밀어 붙이는데, 같은 번호표를 가진 두 사람이 만나면 한 명으로 합쳐지고, 방금 합쳐진 사람은 이번 차례엔 또 합쳐지지 못한다.

### 3-2. 한 줄 예시 (왼쪽으로 밀 때, `·`은 빈 칸)

| 밀기 전 | 밀고 난 뒤 | 이유 |
|---|---|---|
| `2 2 2 2` | `4 4 · ·` | 앞의 2쌍, 뒤의 2쌍이 각각 합쳐짐 (`8` 아님) |
| `2 2 4 ·` | `4 4 · ·` | 2+2=4가 생기지만, 그 4는 옆의 4와 **다시 합쳐지지 않음** |
| `4 2 2 ·` | `4 4 · ·` | 2+2만 합쳐짐 |
| `2 · 2 ·` | `4 · · ·` | 사이 빈 칸은 무시하고 붙인 뒤 합침 |
| `2 2 2 ·` | `4 2 · ·` | 미는 방향(왼쪽) 쪽부터 짝을 지음 |
| `4 4 8 8` | `8 16 · ·` | 두 쌍 각각 합쳐짐 |
| `2 4 8 16` | `2 4 8 16` | 변화 없음 → 이 줄만 보면 움직임 없음 |

오른쪽으로 밀 때는 같은 규칙을 **오른쪽 끝부터** 적용한다. 예: `2 2 2 ·` → 오른쪽 → `· · 2 4`.

### 3-3. 점수 계산

| 상황 | 점수 변화 |
|---|---|
| 2+2 → 4 | +4 |
| 4+4 → 8 | +8 |
| 한 번에 여러 쌍이 합쳐짐 (`2 2 2 2` → `4 4`) | +4 +4 = +8 |
| 새 타일이 생김 | 0 (점수 없음) |
| 움직임 없음 | 0 |

- 현재 점수가 최고 점수보다 커지면 최고 점수도 바로 같이 올라간다.

### 3-4. 끝나는 조건

| 상황 | 결과 |
|---|---|
| 빈 칸이 있음 | 계속 |
| 빈 칸은 없지만, 가로나 세로로 이웃한 같은 숫자가 있음 | 계속 (합칠 수 있으니까) |
| 빈 칸 없고, 이웃한 같은 숫자도 없음 | **게임 오버** |
| 2048 타일이 처음 생김 | **승리 안내** (계속하기는 9번 결정에 따름) |

## 4. 파일 구조

모든 파일은 `apps/game-2048/` 안에 있고, 블로그의 다른 파일(`src/style.css` 등)은 **불러 쓰지 않는다** (색 값은 복사해서 씀).

| 파일 | 역할 | 비유 |
|---|---|---|
| `index.html` | 화면의 뼈대: 제목, 점수 상자, 새 게임 버튼, 게임판 자리, 안내 막 | 건물의 골조 |
| `style.css` | 색·크기·모서리·다크 모드·휴대폰 대응 | 인테리어 |
| `game.js` | 게임 규칙(밀기·합치기·점수·끝 판정)과 조작(키보드·터치), 저장 | 건물 관리인 |
| `spec.md` | 이 계획서 | 설계도 |
| `review.md` | Review 담당의 검사 결과 (나중에 생김) | 검수 보고서 |
| `지침/` | 담당별 작업 지침 | 업무 지시서 |

- 외부 라이브러리·CDN·외부 글꼴 **사용 안 함**. 그림 파일도 필요 없음 (모두 CSS로 그림).
- `index.html`을 **더블클릭해서 바로 열려도** 동작해야 한다 (서버 없이). → `fetch`나 `type="module"`처럼 파일로 열면 막힐 수 있는 기능은 쓰지 않는다.
- (참고) 블로그 빌드(`build.mjs`)가 `apps/` 폴더를 `사이트/`로 복사할지는 아직 정해지지 않았다 → 9번 및 Build 담당 확인 필요. 이 계획서 범위에서는 `build.mjs`를 고치지 않는다.

### game.js 안의 구성 (권장)

| 묶음 | 하는 일 |
|---|---|
| 상태 | 판(4×4 숫자 표), 점수, 최고 점수, 승리 안내 여부, 게임 오버 여부 |
| 규칙 함수 | 한 줄 밀기·합치기, 방향별 이동, 새 타일 놓기, 움직일 수 있는지 검사 |
| 그리기 함수 | 상태를 보고 화면(타일·점수·안내 막)을 다시 그림 |
| 입력 처리 | 키보드, 터치 밀기, 버튼 |
| 저장 | 최고 점수 (선택: 진행 중 게임) 읽기·쓰기, `try/catch`로 감쌈 |

> 규칙 함수는 화면과 분리해 둔다 → "숫자 표를 넣으면 결과 숫자 표가 나오는" 계산만 하도록. 그래야 Review 담당이 8번 예시를 쉽게 시험할 수 있다.

## 5. 화면 동작 설계 (상태를 어떻게 저장하고 그리는지)

### 5-1. 핵심 생각: "장부"와 "게시판"

| 개념 | 쉬운 설명 |
|---|---|
| 상태(장부) | 판의 숫자를 적어 둔 4×4 표. 빈 칸은 0. 예: `[[2,0,0,4],[0,8,0,0],[0,0,16,0],[2,0,0,32]]` |
| 그리기(게시판) | 장부를 보고 화면을 새로 붙이는 일 |
| 원칙 | **화면을 직접 고치지 않고, 장부를 고친 뒤 → 다시 그린다.** 그래서 화면과 장부가 어긋날 일이 없다 |

> 비유: 회계에서 전표(장부)를 먼저 고치고, 보고서(화면)는 전표를 보고 다시 뽑는 것과 같다.

### 5-2. 한 번 조작했을 때의 흐름

```
[키 누름 / 화면 밀기]
        ↓
 방향 알아내기 (왼/오/위/아래)
        ↓
 게임 오버거나 안내 막이 떠 있나? ── 예 → 무시
        ↓ 아니오
 규칙 함수로 새 판 계산 (+ 얻은 점수, 움직였는지)
        ↓
 움직였나? ── 아니오 → 끝 (아무 변화 없음)
        ↓ 예
 장부 갱신 → 점수 더하기 → 최고 점수 갱신·저장
        ↓
 새 타일 1개 놓기
        ↓
 2048 처음 생겼나? / 더 못 움직이나? 확인
        ↓
 다시 그리기
```

### 5-3. 방향 처리 요령 (Build 담당 참고)

- "한 줄을 왼쪽으로 밀기" 함수 하나만 정확히 만든다.
- 오른쪽 = 줄을 뒤집고 → 왼쪽 밀기 → 다시 뒤집기
- 위/아래 = 세로줄을 꺼내서 같은 방식 적용
- → 규칙 코드가 한 곳에만 있어서 실수가 줄어든다.

### 5-4. 그리기 방식

| 항목 | 정함 |
|---|---|
| 판 배경 | 빈 칸 16개를 항상 깔아 둠 (회색 칸) |
| 타일 | 숫자가 있는 칸마다 타일을 그 위에 겹쳐 그림 |
| 숫자 크기 | 1~2자리 크게, 3자리 조금 작게, 4자리 이상 더 작게 (칸 밖으로 넘치지 않게) |
| 크기 단위 | 칸 크기를 화면 폭에 맞춰 비율로 정함 → 작은 휴대폰에서도 정사각형 유지 |
| 애니메이션 | 첫 버전은 없어도 됨(9번 결정). 넣는다면 CSS `transition`(움직임 효과)만 사용, 0.1~0.15초 |
| 접근성 | 점수 상자는 화면 읽기 프로그램이 바뀐 점수를 읽을 수 있게 표시(`aria-live`), 버튼은 키보드로도 누를 수 있게 |

## 6. 휴대폰 대응

### 6-1. 스와이프(화면 밀기) 판정

| 단계 | 방법 |
|---|---|
| 손가락 닿음 | 시작 위치(x, y) 기억 |
| 손가락 뗌 | 끝 위치와의 차이(가로 이동량, 세로 이동량) 계산 |
| 너무 짧음 | 가로·세로 중 큰 쪽이 **30px 미만**이면 무시 (그냥 톡 친 것) |
| 방향 결정 | 가로 이동량이 더 크면 왼/오, 세로가 더 크면 위/아래 |
| 한 번에 한 칸 | 손가락을 한 번 뗄 때 **딱 한 번**만 움직임 |
| 손가락 두 개 | 무시 (확대 동작 등과 섞이지 않게) |

- 마우스·펜·손가락을 한 번에 다루는 `pointer` 이벤트 또는 `touch` 이벤트 중 하나를 쓴다 (Build 담당 판단). 구형 iOS 사파리 호환을 생각하면 `touch` 이벤트가 무난 — **확인 필요**.

### 6-2. 밀 때 화면이 같이 스크롤되지 않게

| 방법 | 설명 |
|---|---|
| 게임판에 `touch-action: none` | 게임판 위에서는 브라우저가 손가락 움직임을 스크롤로 쓰지 않음 |
| 터치 이동 중 `preventDefault` | 위 방법이 안 먹는 브라우저를 위한 보조 (이벤트 등록 시 `passive: false`) |
| 게임판 밖 | 평소처럼 스크롤 가능 (페이지 전체를 막지 않음) |
| 키보드 | 방향키를 누를 때 페이지가 스크롤되지 않게 기본 동작 막기 (게임 키일 때만) |

### 6-3. 작은 화면 크기 맞춤

| 항목 | 규칙 |
|---|---|
| 좌우 여백 | 16px |
| 판 크기 | `화면 폭 − 32px`와 `480px` 중 작은 값, 정사각형 |
| 가로 스크롤 | 없음 (375px 폭에서 확인) |
| 아주 작은 화면(320px) | 제목·점수 상자가 두 줄로 내려가도 됨, 숫자는 칸 밖으로 넘치지 않음 |
| 화면 높이가 낮을 때 | 판이 화면 높이의 약 70%를 넘지 않게 (가로로 눕힌 휴대폰·iframe 대비) |
| 확대 | 두 번 톡 쳐서 확대되는 것 방지(`touch-action`), 단 사용자의 손가락 벌려 확대는 막지 않음 |

### 6-4. iframe으로 넣을 때 고려

- 블로그 첫 화면에 `<iframe>`(다른 페이지를 창문처럼 끼워 넣는 기능)으로 넣을 수 있다.
- iframe 안에서는 **키보드 입력이 게임판을 한 번 눌러야** 들어간다 → 안내 문구 "판을 누른 뒤 방향키" 표시 고려.
- iframe 안에서 방향키가 블로그 페이지를 스크롤하지 않도록 키 기본 동작 막기.
- 다크 모드는 iframe 안에서도 `prefers-color-scheme`으로 따로 판단된다. 단, 블로그에서 사용자가 직접 고른 모드(블로그 `localStorage`)는 게임이 알 수 없다 → 9번 결정 항목.

## 7. 저장 (localStorage)

> `localStorage` = 브라우저 안의 작은 메모장. 창을 닫아도 남는다. 다른 사람·다른 기기와는 공유되지 않는다.

| 저장 이름(키) | 내용 | 언제 쓰나 | 필수? |
|---|---|---|---|
| `game2048.best` | 최고 점수(숫자) | 최고 점수가 바뀔 때 | 필수 |
| `game2048.state` | 진행 중 판, 현재 점수, 승리 안내 여부 | 매 이동 후 | 선택(S4) |

- 이름 앞에 `game2048.`을 붙여 블로그 저장값(모드 설정 등)과 섞이지 않게 한다.
- **모든 읽기·쓰기는 `try/catch`로 감싼다.** 저장이 막힌 환경(시크릿 창, 설정 차단, 일부 iframe)에서는 저장만 안 되고 게임은 정상 진행.
- 읽은 값이 이상하면(숫자가 아님, 판 모양이 4×4가 아님, 음수 등) **버리고 새로 시작**한다.
- 최고 점수 읽기 실패 시 0으로 시작.

### 8-2. 방향별 확인

- [ ] 오른쪽: `2 2 2 ·` → `· · 2 4` (오른쪽 끝부터 짝지음)
- [ ] 오른쪽: `2 2 2 2` → `· · 4 4`
- [ ] 위·아래: 세로줄에도 같은 규칙이 적용됨 (8-1의 예를 세로로 놓고 확인)
- [ ] 네 방향 모두 "한 타일은 한 번만 합쳐짐" 지켜짐

### 8-3. 진행 규칙

- [ ] 판이 전혀 안 바뀌는 방향으로 밀면 **새 타일이 생기지 않고** 점수도 그대로
- [ ] 판이 바뀌면 새 타일이 **정확히 1개** 생김, 빈 칸에만 생김
- [ ] 새 게임 시작 시 타일이 **정확히 2개**
- [ ] 새 타일이 2 또는 4만 나옴 (여러 번 시험해 대략 9:1 비율 — 예: 1000번 중 4가 약 100번)
- [ ] 점수 = 합쳐진 타일 숫자의 합
- [ ] 최고 점수가 현재 점수를 따라 올라가고, 새 게임 후에도 남아 있음
- [ ] 새 게임 버튼: 판·현재 점수 초기화, 최고 점수 유지, 안내 막 사라짐
- [ ] 게임 오버: 빈 칸 없음 + 이웃 같은 숫자 없음일 때만. **빈 칸은 없지만 합칠 수 있는 판에서는 게임 오버가 아님**
  - 예: `2 4 2 4 / 4 2 4 2 / 2 4 2 4 / 4 2 4 4` → 오른쪽 아래 `4 4`가 있으므로 계속
  - 예: `2 4 2 4 / 4 2 4 2 / 2 4 2 4 / 4 2 4 2` → 게임 오버
- [ ] 2048 안내는 **처음 한 번만** 뜸 (계속하기를 넣는 경우, 이후 또 2048을 만들어도 다시 안 뜸)
- [ ] 안내 막이 떠 있는 동안 방향키·밀기가 판을 움직이지 않음

### 8-4. 조작

- [ ] 방향키 4개, WASD(대·소문자) 동작
- [ ] 한글 입력 상태에서 WASD — 동작 여부 **확인 필요** (`event.code` 사용 시 동작). 방향키는 항상 동작해야 함
- [ ] 키를 누르고 있어도 폭주하지 않음 (자동 반복 키를 막거나, 이동이 정상 처리되는지)
- [ ] 방향키를 눌러도 페이지가 스크롤되지 않음
- [ ] 입력칸이 없으므로 다른 키는 무시됨, 단 Tab으로 버튼 이동은 가능
- [ ] 휴대폰: 상하좌우 밀기 각각 동작, 짧게 톡 치면 안 움직임, 게임판 위에서 밀 때 화면이 스크롤되지 않음

### 8-5. 화면·저장·보안

- [ ] 기본/다크 모드 둘 다 모든 타일 숫자가 잘 읽힘 (대비 확인)
- [ ] 375px·320px 폭에서 가로 스크롤 없음, 4자리 숫자(1024, 2048)가 칸 밖으로 안 넘침
- [ ] `index.html` 더블클릭으로 열어도 동작 (서버 없이)
- [ ] 외부 파일(CDN·외부 글꼴·블로그의 다른 파일)을 불러오지 않음
- [ ] 시크릿 창 또는 저장 차단 상태에서도 오류 없이 게임 진행 (개발자 도구 콘솔에 빨간 오류 없음)
- [ ] 저장값을 일부러 이상하게 바꿔도(예: `game2048.best`에 "abc") 게임이 정상 시작
- [ ] 코드에 한글 주석이 짧게 달려 있음
- [ ] 개인 정보·회사 정보·PC 경로가 파일에 없음 (공개 저장소)
