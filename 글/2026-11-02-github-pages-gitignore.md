이 블로그를 GitHub에 올리고 **GitHub Pages**로 공개하기 전에 정해야 할 것이 두 가지 있었습니다.

1. 블로그를 **어떻게** 배포할까?
2. 프로젝트 파일 중 **어디까지** 올릴까?

> [!note] 먼저 용어 정리
> - **Git**: 파일의 변경 기록을 남기는 프로그램. 내 PC의 숨김 폴더 `.git`에 기록이 저장됩니다.
> - **GitHub**: Git 기록을 올려 두는 인터넷 저장소.
> - **GitHub Pages**: GitHub 저장소의 HTML 파일을 웹사이트로 공개해 주는 무료 서비스.

## 1. 배포 방식: 자동 vs 수동

두 방식 모두 결과는 같은 블로그 주소입니다. 차이는 **누가, 언제 빌드해서 올리느냐**입니다.

| | 자동 배포 (GitHub Actions) | 수동 배포 (배포.bat) |
|---|---|---|
| 비유 | 결재함에 서류만 넣으면 **담당자가 알아서 인쇄해 게시판에 붙임** | **내가 직접 인쇄해서** 게시판에 붙임 |
| 글 올릴 때 할 일 | 커밋하고 올리기(push) | `배포.bat` 더블클릭 |
| 빌드하는 곳 | GitHub 서버 (1~2분 뒤 반영) | 내 PC |
| 원본 백업 | 글을 올리는 것 자체가 백업 | 블로그 게시와 원본 백업이 **별개** |
| 처음 준비 | 자동 작업 권한(workflow) 추가 1번 | 없음 |
| 다른 기기에서 수정 | GitHub 웹에서 고쳐도 자동 반영 | 빌드할 PC가 있어야 함 |
| 실수할 여지 | 적음 | 빌드·업로드 중 하나를 빠뜨릴 수 있음 |

### 자동 배포는 어떻게 동작하나

저장소에 `.github/workflows/deploy.yml`이라는 **작업 지시서**를 넣어 둡니다.

```yaml
on:
  push:
    branches: [main]      # main에 올라오면
jobs:
  build:
    steps:
      - run: node build.mjs   # 블로그를 빌드하고
      # → 사이트 폴더를 GitHub Pages에 게시
```

"main에 새 버전이 올라오면 → 빌드하고 → 게시하라"는 지시서입니다. 한 번 넣어 두면 그다음부터는 글을 올리기만 하면 됩니다.

> [!tip] 이 블로그의 선택
> **자동 배포**로 정했습니다. 처음 준비가 한 번뿐이고, 그 뒤로는 원본 백업과 블로그 게시가 한 번에 되기 때문입니다.

## 2. 올릴 범위 정하기: .gitignore

Git에 올릴 파일은 **내가 고를 수 있습니다.** 프로젝트 폴더에 `.gitignore`라는 파일을 두고, 올리지 않을 파일을 적으면 됩니다.

```
사이트/            ← 빌드 결과물 (언제든 다시 만들 수 있음)
CLAUDE.local.md    ← 개인 메모
*.pdf              ← 이런 식으로 종류별로도 가능
```

| | 내용 |
|---|---|
| 비유 | 결재 대장의 **"보관 제외 목록"** |
| 적힌 파일 | PC에는 그대로 있고, Git 기록과 GitHub에만 안 들어감 |
| 적는 단위 | 파일 하나, 폴더 전체, `*.확장자`처럼 종류별 |

### 알아 둘 한계 세 가지

> [!warning] 1. 파일 단위로만 된다
> 파일 **안의 특정 줄만** 숨길 수는 없습니다. 일부 내용만 숨기려면 그 내용을 다른 파일로 옮긴 뒤 그 파일을 제외해야 합니다.

> [!warning] 2. 이미 커밋한 파일은 기록에 남아 있다
> 보관 제외 목록은 **앞으로 들어올 파일**에만 적용됩니다. 이미 커밋한 파일을 목록에 추가해도 예전 기록에는 남아 있습니다. GitHub에 올리기 **전에** 정리하는 것이 가장 쉽습니다.

> [!warning] 3. 공개 저장소에서 일부만 비공개는 불가
> 무료 계정의 GitHub Pages는 **공개 저장소**가 필요합니다. 공개 저장소에 올린 파일은 모두 공개되며, 숨기려면 아예 올리지 않는 방법뿐입니다.

### 실제로 적용한 방법: CLAUDE.md 나눠서 올리기

`CLAUDE.md`는 Claude Code가 작업할 때 먼저 읽는 **인수인계서**입니다. 블로그를 만드는 데는 쓰이지 않으므로 올리지 않아도 블로그에는 영향이 없습니다. 하지만 올리지 않으면 백업과 버전 기록이 사라집니다.

그래서 **나눠서** 올렸습니다.

| 파일 | 내용 | GitHub |
|---|---|---|
| `CLAUDE.md` | 블로그 목적, 디자인, 기술 규칙 | 올림 (공개) |
| `CLAUDE.local.md` | 개인 정보, PC 경로 같은 내용 | 올리지 않음 (`.gitignore`) |

`CLAUDE.md` 안에 `@CLAUDE.local.md` 한 줄을 넣어 두면, 내 PC의 Claude는 두 파일을 모두 읽어 전과 똑같이 일합니다.

### 하나 더: 커밋 기록의 이메일

커밋에는 작성자 이메일이 함께 기록되고, 공개 저장소에서는 이것도 보입니다. GitHub가 주는 **가림 이메일**(`...@users.noreply.github.com`)을 쓰면 실제 이메일을 숨긴 채 내 계정의 커밋으로 표시됩니다.

## 정리

- [x] 배포는 **자동 배포**: 올리기만 하면 GitHub가 빌드·게시
- [x] 올릴 범위는 **.gitignore**로 지정: 빌드 결과물과 개인 메모는 제외
- [x] 공개 저장소에 올리기 **전에** 개인 정보 정리하기
