거부(deny) 규칙을 설정하고 나니 두 가지가 궁금해졌습니다.

1. 설정한 권한은 **어디서 확인**할까?
2. 책에 나온 **샌드박스 모드**는 무엇이고, 내 PC에는 켜져 있을까?

## 1. 권한 확인하는 법

권한을 보는 명령은 `/permissions`입니다. 다만 이 명령은 **터미널 화면 안에 창을 띄우는 방식**이라, Claude 데스크톱 앱(Code 탭)에서는 작동하지 않습니다.

| 방법 | 어디서 | 하는 법 | 특징 |
|---|---|---|---|
| ① `/permissions` | 터미널 | `claude` 실행 → `/permissions` 입력 | 규칙을 목록으로 보고 바로 추가·삭제 가능 |
| ② 설정 파일 열기 | 메모장, VS Code | `~/.claude/settings.json` 열기 | 저장된 원본을 그대로 봄 |
| ③ Claude에게 묻기 | 데스크톱 앱 | "권한 설정 보여줘" | 가장 간단, 표로 정리해 줌 |

> [!note] ①이 더 많이 보일 수 있다
> `/permissions` 화면에는 PC 전체 설정 말고도 **프로젝트 설정**과 **대화 중 "항상 허용"을 눌러 생긴 규칙**까지 함께 보입니다.

## 2. 샌드박스 모드란?

**Claude가 실행하는 명령을 '울타리 친 방' 안에서만 돌리는 기능**입니다. 명령이 무엇이든 정해진 폴더 밖의 파일을 고치거나 허락되지 않은 인터넷 주소에 접속할 수 없게 **운영체제가** 막아 줍니다.

### 권한 규칙과의 차이

| | 권한 규칙 (deny/ask) | 샌드박스 |
|---|---|---|
| 비유 | 출입구 경비원이 **명단을 보고** 막음 | 아예 **벽이 있는 작업실**에서만 일하게 함 |
| 막는 기준 | 명령의 **글자 모양** (`rm -rf`로 시작하는가?) | 명령이 **실제로 하는 일** (어느 파일을 고치나, 어디에 접속하나) |
| 빈틈 | 같은 일을 다른 모양으로 쓰면 통과 (`rm -fr`) | 모양과 상관없이 벽 밖으로는 못 나감 |
| 누가 막나 | Claude Code 프로그램 | 운영체제 |

> [!tip] 둘은 함께 쓰는 것
> 권한 규칙은 1차 관문, 샌드박스는 2차 안전벽입니다. 경비원이 놓친 사람이 들어와도 작업실 벽 때문에 금고까지는 못 갑니다.

### 보통 막는 것

| 항목 | 기본 동작 |
|---|---|
| 파일 쓰기 | **작업 폴더 안**에서만 가능 |
| 파일 읽기 | 대부분 가능 (설정으로 더 막을 수 있음) |
| 인터넷 | **허용한 주소만** 접속 가능 |

### 켜는 방법

| 방법 | 내용 |
|---|---|
| 터미널 Claude Code | `/sandbox` 입력 → 화면에서 켜기 |
| 설정 파일 | `settings.json`에 `"sandbox": { "enabled": true }` 추가 |

> [!warning] 윈도우 지원
> 공식 샌드박스는 **맥과 리눅스(WSL2 포함)** 위주로 만들어졌습니다. 일반 윈도우에서 얼마나 지원되는지는 아직 확인하지 못했습니다.

## 3. 내 PC에 켜져 있는지 시험

설정 파일만 보지 않고 **실제로 벽이 있는지** 시험해 봤습니다.

| 확인 항목 | 결과 | 뜻 |
|---|---|---|
| PC 전체 설정 `~/.claude/settings.json` | `sandbox` 항목 없음 | 켜는 설정이 없음 |
| 프로젝트 설정 `.claude/settings.json` | 파일 없음 | 프로젝트에서도 안 켬 |
| 샌드박스 관련 환경 변수 | 없음 | 샌드박스 프로그램이 돌고 있지 않음 |
| **프로젝트 밖** 홈 폴더에 시험 파일 쓰기 | ✅ 써짐 (바로 지움) | **벽이 없음**. 켜져 있었다면 막혔을 것 |

결론: **샌드박스는 꺼져 있습니다.**

> [!example] 시험 요령
> "벽이 있다면 막혀야 할 일"을 **무해하게** 해 봅니다. 프로젝트 밖에 빈 시험 파일을 하나 쓰고, 써지면 바로 지웁니다. 거부 규칙을 시험할 때 "없는 폴더 지우기"를 썼던 것과 같은 생각입니다.

### 착각했던 것

전에 `curl`로 블로그 주소를 확인하다 SSL 오류가 나서, 샌드박스 때문이라고 짐작했었습니다. 시험해 보니 샌드박스는 꺼져 있었으므로 **다른 원인**입니다. 회사 네트워크나 보안 프로그램이 인터넷 인증서를 검사하면서 생겼을 수 있지만, 정확한 원인은 아직 모릅니다.

## 지금 내 PC를 지켜 주는 것

| 장치 | 상태 |
|---|---|
| 권한 규칙 (deny 16개, ask 9개) | ✅ 켜짐. 위험한 명령은 이름으로 막음 |
| 샌드박스 (벽) | ❌ 꺼짐 |
| 앱의 승인 요청 | ✅ 위험해 보이는 작업은 실행 전에 물어봄 |

## 정리

- [x] 권한은 터미널의 `/permissions` 또는 `settings.json`에서 확인
- [x] **권한 규칙**은 이름으로 막고, **샌드박스**는 벽으로 막는다
- [x] 설정 파일만 믿지 말고 **무해한 시험**으로 실제 동작을 확인
- [x] 짐작은 시험으로 바로잡기 (SSL 오류 ≠ 샌드박스)
